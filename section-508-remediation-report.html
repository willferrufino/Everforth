Sample remediation log
IDFindingAccessibility requirementSeverityRemediationStatus
A11Y-01 Form input had placeholder text but no programmatic label. Form controls need an accessible name and clear instructions. High Add a visible <label> tied to the input with matching for and id values. Validated
A11Y-02 Hero image description repeated nearby visible text. Text alternatives should communicate purpose without unnecessary repetition. Medium Use concise alt text when the image adds meaning; use empty alt text when it is decorative. Fixed
A11Y-03 Keyboard focus was difficult to see on dark navigation. Interactive controls need a visible focus indicator. High Add a high-contrast focus outline and test every navigation item using only the keyboard. Open
A11Y-04 Generic “Learn more” links did not explain their destination out of context. Link purpose should be understandable from the link text or accessible context. Low Replace generic text with descriptive links such as “Read the digital accessibility guidance.” Validated

Remediation documentation

Example: accessible form label

Issue: A placeholder disappears after entry and may not provide a reliable accessible name.

<label for="email">Email address</label>
<input id="email" name="email" type="email"
       autocomplete="email">

Validation: Confirm the label is visible, programmatically associated, keyboard reachable, and announced with the field.

Example: heading hierarchy

Issue: Visual styling was used instead of structural headings.

<h1>Digital services</h1>
  <h2>What this office does</h2>
    <h3>Improve digital services</h3>

Validation: Review the heading outline without CSS and confirm the hierarchy matches the page structure.

Example: keyboard focus styling 
a:focus,
button:focus,
input:focus {
  outline: 4px solid #face00;
  outline-offset: 3px;
}

Validation: Tab through the page from top to bottom and confirm focus is never hidden or lost.
